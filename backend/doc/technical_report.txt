Защита API:


2.3. Пул соединений (реализовано в connection_pool.cpp):
Структура:
```cpp
class ConnectionPool {
private:
    std::queue<std::unique_ptr<pqxx::connection>> connections;
    std::mutex mutex;
    std::condition_variable condition;
    std::string connectionString;
    static const int POOL_SIZE = 10;
    static const int CONNECTION_TIMEOUT = 5;
};
```

Принцип работы:
1. При инициализации создается 10 базовых соединений
2. При запросе соединения:
   - Если есть свободное - возвращается из очереди
   - Если нет свободных:
     * Ожидание до 5 секунд освобождения
     * При таймауте создается новое соединение
3. После использования соединение возвращается в пул

Масштабирование:
- Пул из 10 соединений - это базовый размер
- Сервис может обслуживать намного больше клиентов
- При нехватке соединений создаются новые
- Неиспользуемые соединения автоматически закрываются

Пример использования:
```cpp
auto conn = ConnectionPool::getConnection();
if (!conn) throw std::runtime_error("Failed to get connection");

pqxx::work txn(*conn);
// ... работа с БД ...
txn.commit();

ConnectionPool::releaseConnection(std::move(conn));
```

3. API ЭНДПОИНТЫ
----------------
3.1. Аутентификация:
POST /api/auth/login
- Входные данные: personnel_number, password
- Возвращает: данные пользователя и JWT токен
- Логика: проверка учетных данных, генерация токена

POST /api/auth/register
- Входные данные: personnel_number, password, full_name и другие поля сотрудника
- Возвращает: данные созданного пользователя
- Логика: создание учетной записи и профиля сотрудника

3.2. Новости:
GET /api/news
- Параметры: current_user_id
- Возвращает: массив новостей с лайками, комментариями и информацией о закреплении
- Логика: объединение данных из таблиц news, news_likes, news_comments

POST /api/news
- Входные данные: title, content, author_id, image_data (опционально)
- Возвращает: созданную новость
- Логика: сохранение новости и изображения в БД

PUT /api/news/{id}
- Входные данные: title, content, image_data
- Возвращает: обновленную новость
- Логика: обновление новости, обработка изображения

DELETE /api/news/{id}
- Логика: удаление новости и связанных данных (лайки, комментарии)

POST /api/news/{id}/like
- Входные данные: employee_id
- Возвращает: обновленное количество лайков
- Логика: переключение состояния лайка

POST /api/news/{id}/comments
- Входные данные: employee_id, text
- Возвращает: созданный комментарий
- Логика: добавление комментария, уведомление через WebSocket

POST /api/news/{id}/pin
- Входные данные: isPinned
- Логика: управление закреплением новости

3.3. Сотрудники:
GET /api/employees
- Возвращает: массив сотрудников со всеми связанными данными
- Логика: сложный JOIN запрос с организациями, отделами, локациями

GET /api/employees?personnel_number={number}
- Возвращает: данные конкретного сотрудника
- Логика: поиск по табельному номеру

PUT /api/employees/{id}
- Входные данные: все поля сотрудника
- Логика: обновление данных с проверкой связей

3.4. Организационная структура:
GET /api/organizations
GET /api/departments
GET /api/locations
- Возвращают: справочные данные
- Логика: оптимизированные запросы с кэшированием

3.5. Порталы:
GET /api/links
- Возвращает: список внутренних порталов с иконками
- Логика: обработка бинарных данных иконок

POST /api/links
PUT /api/links/{id}
DELETE /api/links/{id}
- Логика: управление порталами, обработка изображений

3.6. Дни рождения:
GET /api/birthdays/upcoming
- Возвращает: список ближайших дней рождения
- Логика: сложный расчет дат, кэширование результатов

5.4. Кэширование подготовленных запросов:
```cpp
std::string stmt_name = "get_news_" + std::to_string(reinterpret_cast<uintptr_t>(conn.get()));
try {
    txn.conn().prepare(stmt_name, query);
    result = txn.exec_prepared(stmt_name);
    txn.exec0("DEALLOCATE " + stmt_name);
} catch (...) {
    result = txn.exec_params(query, currentUserId);
}
```

5.5. Обработка ошибок:
- Try-catch блоки во всех критических операциях

6.3. Реализация тестов:
```cpp
void LoadTester::runTestThread(const std::string& endpoint) {
    httplib::Client cli(LoadTestConfig::SERVER_URL);
    cli.set_connection_timeout(LoadTestConfig::REQUEST_TIMEOUT_MS);
    cli.set_keep_alive(true);
    
    for (int i = 0; i < LoadTestConfig::getRequestsPerThread(); ++i) {
        auto start = std::chrono::high_resolution_clock::now();
        auto res = cli.Get(endpoint.c_str(), headers);
        auto end = std::chrono::high_resolution_clock::now();
        double duration = std::chrono::duration<double, std::milli>(end - start).count();

        if (res) {
            metrics.addResponse(duration, res->status);
        } else {
            metrics.addResponse(duration, 0);
        }
        
        std::this_thread::sleep_for(std::chrono::milliseconds(LoadTestConfig::REQUEST_DELAY_MS));
    }
}
```
